# 为什么 llama-fit-params 会返回 `-c 0`

[English](why-fit-params-returns-c-0.md) | [简体中文](why-fit-params-returns-c-0.zh-CN.md)

很多人第一次看到 `llama-fit-params` 输出 `-c 0 -ngl -1` 时会感到困惑：显存只有 8 GB，凭什么能全量卸载？`-c 0` 又是什么意思？本文把这两件事拆开讲清楚。

---

## 先纠正一个概念误区

`-ngl` 的含义很容易被理解反：

- `-ngl` 全称 `n-gpu-layers`，指**卸载到 GPU 上运行的模型层数**
- `-ngl -1` 代表**把全部模型层都卸载到 GPU 显存中运行**，是拉满 GPU 加速的配置，**不是"不需要 GPU 卸载"**
- 真正"完全不 GPU 卸载、全 CPU 跑"的参数是 `-ngl 0`

---

## 为什么 8 GB 显存也支持全量 GPU 卸载（`-ngl -1`）

`llama-fit-params` 会自动计算「模型权重 + KV 缓存 + 运行时开销」的总显存占用，只要总占用能完整塞进你的显存（扣除预留余量），就会推荐全层卸载。以 Gemma 4 E4B Q4_K_M 在 8 GB 显存上的场景为例，总占用远小于 8 GB，拆解如下。

### 1. 模型权重本身占用极低

**Gemma 4 E4B Q4_K_M** 属于小参数量 + 中等量化的模型：

- 参数量：4B（40 亿）
- 量化精度：Q4_K_M（平均约 4.5 bit/参数）
- 实际显存占用：仅 **2.4~2.7 GB**

也就是说，仅模型权重只占 8 GB 显存的不到三分之一，剩余空间非常充足。

### 2. KV 缓存占用远低于剩余显存

KV 缓存是推理时存储历史注意力数据的部分，占用和上下文长度成正比；开启 `q8_0` 8-bit 量化 KV 缓存后，显存消耗进一步压缩。

以 Gemma 4 E4B 的架构（34 层、隐藏维度 2560）计算，8-bit 量化 KV 缓存的占用：

| 上下文长度 | KV 缓存预估占用 |
|------------|----------------|
| 32768（32K） | ~0.34 GB |
| 131072（128K） | ~1.35 GB |

### 3. 总显存占用合计

128K 上下文的满载场景下：

模型权重（~2.6 GB） + KV 缓存（~1.35 GB） + CUDA 运行时/中间张量（~0.5 GB） ≈ **4.45 GB**

再扣除通过 `--fit-target 512` 预留的 512 MB 显存余量（留给系统和驱动），剩余可用显存仍有 7.5 GB，远高于实际需求。因此工具判定可以把全部模型层都放进 GPU，不需要留任何层在 CPU 上运行。

---

## 补充：输出里的 `-c 0` 是什么

`-c` 是上下文长度参数，`-c 0` 代表**使用模型内置的默认上下文窗口**，不需要手动限制长度。因为指定的 32K/128K 都完全在显存承受范围内，工具不需要压缩上下文，因此输出 `0`，直接使用模型原生支持的窗口即可。

如果后续换成更大的模型（比如 9B、13B）、更高精度的量化版本，或者开更大的上下文，总占用超过显存容量时，工具就会自动减少 `-ngl` 的数值，把一部分层放回 CPU 运行，也就是"部分 GPU 卸载"。
